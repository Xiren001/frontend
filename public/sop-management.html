Proofreader Payments ⭐

💰
Your most important recurring task Process payments to proofreaders for completed products. Only management and admin can access this page.

The Proofreader Payments page shows every product that has been or is being proofread, across all languages and months. Use it to track who has been paid and to process new payments.

Locating Unpaid Products

  1. Open Proofreader Payments from the left sidebar.
  2. Click the Unpaid tab — this filters to products with status Done that have not yet been paid.
  3. Use the month picker (top right) to select the billing period.
  4. Use the language pills to focus on one language at a time, or leave on All to see everything.
  5. Use the Week tabs to filter by week if needed.

Processing a Payment

  1. Find the product row — confirm the proofreader name and language are correct.
  2. Click $ Mark Paid on the row. The button only appears for products with status Done.
  3. The row moves to the Paid tab and the payment date is recorded automatically.
  4. Repeat for all done products in the period.
⚠️
Only "Done" products can be marked paid
Products still In Proofread, Ready, Needs Links, or Active are visible for tracking but cannot be paid yet. Wait until their status changes to Done before processing payment.

Understanding Product Statuses

StatusMeaningAction
DoneProofreading complete — proof_end date is setMark Paid once payment is processed
In ProofreadCurrently being proofread — not finished yetNo action yet — wait for Done
ReadyProofreader has marked it ready for revisionNo action yet — wait for Done
Needs LinksPDP URL or Drive folder not yet addedFollow up with website team
ActiveProduct is in progress with no special flagNo action yet

Undoing a Payment

  1. Switch to the Paid tab to find the paid product.
  2. Click the ↩ Undo button on the row.
  3. The product returns to Unpaid and the payment date is cleared.
💡
Use the All tab for a full overview
The All tab shows every product regardless of pay status — useful for cross-checking before finalising a payment run. The Direct week tab shows products added directly into the proofreading module (not from the tracker).
2

Proofread Queue

The Proofread Queue is your live view of everything currently in proofreading — grouped by week and language. Use it to monitor progress and catch overdue items.

Daily Check

  1. Open Proofread Queue — default opens the Active tab for the current month.
  2. Scan for any row flagged RED — these have been in proofread for more than 3 days (the SLA).
  3. Follow up with the assigned proofreader for any red items.
  4. Use the language pills to filter by language if you manage a specific market.

Reviewing Completed Work

  1. Click the Done tab.
  2. Select the month using the month picker (top right).
  3. Review completed proofreadings — use this to verify before processing payments.
💡
Direct tab = products added without a tracker build
The Direct week tab shows products that were added straight into the Proofreading module, not via the Jewelry or Funnel Tracker. These still go through the full proofread process and appear in Proofreader Payments.
3

Proofreading (Copy Review)

The Proofreading module is where proofreaders log corrections and where website / ads teams apply them. As management, you have read access to monitor the state of all products and can add products directly.

Monitoring Products

  1. Open Proofreading from the sidebar.
  2. Select a language from the top filter to see that language's products.
  3. Click any product to view corrections, links, and current status in the right panel.
  4. Use the search bar to find a specific product by name.

Adding a Product Directly

  1. Click the + Add product button.
  2. Fill in the product name, language, proofreader, PDP URL, Drive folder link, week, and month.
  3. Click Save — the product is immediately visible in the queue and in Proofreader Payments.
⚠️
Always set the PDP URL and Drive folder
Proofreaders cannot start reviewing until both links are filled in. Products missing links show status Needs Links and are locked for the proofreader.

Jewelry & Funnel Tracker

The trackers show the full build pipeline — from product approval through build, proofread, and testing phases.

Reading the Tracker

Column / FieldWhat it shows
Approved dateWhen the product was approved to start building
Build startWhen the build phase began
Into ProofreadWhen it entered the proofread queue — triggers a record in Proofread Queue
Proof endWhen proofreading finished — triggers a Done status in Payments
TestingPhase after proofread — outcome decided here
OutcomeTesting / Expanding / Stopped

What to Look For

  • Products where Into Proofread is set but Proof end is blank — still being proofread. Cross-reference with the Proofread Queue.
  • Products where Proof end is set — these should appear in Proofreader Payments as Done and may need to be paid.
  • Builds without a proofreader assigned — follow up so the proofread queue has correct ownership.
💡
Tracker → Proofread Queue → Payments are linked
When a build's "Into Proofread" date is set, it automatically appears in the Proofread Queue. When "Proof end" is set, it becomes Done in Proofreader Payments and is ready to be paid.
5

Mistake Log

The Mistake Log tracks proofreading errors by product, proofreader, and language. Use it to evaluate quality before processing payments and to identify recurring issues.

When to Use It

  • Before a payment run — review whether a proofreader has a pattern of frequent critical mistakes
  • When a product comes back with many corrections — check if it is a systemic issue
  • During performance reviews for proofreaders

Key Filters

  • Filter by language to see one market's quality at a glance
  • Filter by proofreader to compare individual performance
  • Filter by severity — focus on Critical and Medium mistakes for payment decisions
6

Weekly & Monthly Reports

Reports give you a structured summary of pipeline performance — volume, speed, and quality across all languages and build types.

Weekly Report

  1. Open Weekly Report from the sidebar.
  2. Select the week to review.
  3. Review throughput (builds completed, products proofread) and flag any weeks where output was below target.

Monthly Report

  1. Open Monthly Report.
  2. Select the month.
  3. Use the monthly totals to cross-reference against payment volumes — total paid products should match total done proofreadings in Proofreader Payments for the same month.
✅
Payment reconciliation tip
At the end of each month, open the Monthly Report and Proofreader Payments side by side. The count of Done proofreadings in the report should match the Paid + Unpaid (done) count in Payments. Any gap means a product was completed but not yet paid.
7

Decision Rights

The Decision Rights page is a reference document that defines who owns which decisions across the team. Consult it before making structural changes to workflows, assignments, or process rules.

  • Use it to confirm whether a payment or process change needs admin sign-off or can be handled by management directly
  • Reference it when onboarding new proofreaders to clarify their scope
  • Check it if there is a dispute about who is responsible for a step in the pipeline
